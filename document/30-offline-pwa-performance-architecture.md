# 30) هندسة PWA الخفيفة Offline والأداء (Offline PWA & Performance Architecture)

**تاريخ الإصدار:** أكتوبر 2026
**سقف الصدق الملزم:** لا ندّعي «يعمل على كل جهاز في العالم». نعرّف **Baseline واقعيًا** ومصفوفة توافق وخطة fallback، ونختبر على أجهزة ضعيفة فعلية.

---

## 1) التخزين Offline — الآليات المعتمدة [حقيقة موثقة — web.dev]

- **Cache Storage** لأصول الشبكة: HTML/CSS/JS/الصور/الصوت.
- **IndexedDB** للبيانات المنظمة: فصول JSON، تخصيص البيت، الترخيص الموقّع.
- **WebStorage** غير موصى به للبيانات المعقدة (متزامن وغير متاح داخل Service Worker).
- **`StorageManager.persist()`** لطلب تخزين دائم يمنع الإخلاء التلقائي — **لكن المستخدم يبقى قادرًا على حذف البيانات في أي وقت** حتى بعد منح الاستمرارية. [web.dev/offline-data](https://web.dev/learn/pwa/offline-data)

[توصية] لذلك: الترخيص الموقّع + أقل حزمة محتوى تُخزن في IndexedDB مع persist، وعند الحذف يعيد العميل فتح رابطه الشخصي (إعادة تفعيل مجانية ضمن حد الأجهزة).

## 2) قابلية التثبيت — اختلافات المنصات [حقيقة موثقة — web.dev]

| المنصة | السلوك | الأثر على التصميم |
|---|---|---|
| Android/Chrome | Install prompt آلي؛ يُثبَّت WebAPK (يدعم badging/shortcuts) أو shortcut محدود أو QuickApp حسب الجهاز والمتصفح | نعرض prompt الأصلي + تعليمات بديلة |
| iOS/iPadOS | **لا يوجد install prompt إطلاقًا**؛ الإضافة يدوية عبر Share → Add to Home Screen؛ المثبتة تظهر في الشاشة الرئيسية وSpotlight وSiri Suggestions، وتفتقر لـbadging وapp shortcuts، وبعض المتصفحات تنشئ shortcut محدودًا فقط | **دليل إضافة مصوّر من 3 خطوات داخل الصفحة نفسها** — خطوة إلزامية في أول تفعيل، لا افتراض أن المستخدم يعرف |

[web.dev/installation](https://web.dev/learn/pwa/installation)

## 3) F) نموذجا التسليم والتوصية

| النموذج | الوصف | الحكم |
|---|---|---|
| (1) Hosted PWA | رابط شخصي + تفعيل + Offline caching | **الموصى به أساسًا** — ترخيص وتحديث وHand-over |
| (2) Exported offline package | ملف يُحمَّل يعمل بلا خادم — ميزة VIP | مؤجل؛ أضعف حماية وأثقل اختبارًا؛ يُقدَّم لاحقًا كنسخة «تملّك» للباقة الأعلى مع watermark أقوى |

## 4) G) ميزانية أداء واقعية [توصية — أهداف هندسية تُقاس، لا ادعاءات]

| البند | السقف المستهدف | ملاحظات |
|---|---|---|
| Initial shell (HTML+CSS+JS حرج) | ≤ 150 KB مضغوطًا | بلا إطار ثقيل؛ vanilla JS أو مايكرو-مكتبة |
| إجمالي JS/CSS | ≤ 300 KB مضغوطًا | code splitting لكل وجهة |
| الخطوط | ≤ 2 عائلة، subset للغات المفعّلة فقط | تحميل شرطي حسب لغة العاملة |
| Chapter JSON | ≤ 50 KB للفصل | تحميل كسول عند فتح الفصل |
| الصور | WebP/AVIF، ≤ 100 KB للصورة، lazy-load | صور أجهزة البيت تُضغط server-side عند الرفع |
| الصوت لكل فصل | ≤ 500 KB (Opus 32–48kbps) | يُبث ولا يُحمَّل كاملًا إلا عند persist |
| RAM على جهاز ضعيف | ≤ 150 MB قياس عملي | Lazy DOM (لا تُبنى وجهة إلا عند دخولها) |
| دورة حياة الصوت | كائن `Audio` واحد مُعاد الاستخدام؛ `pause`+`src=""`+`load()` عند التبديل | يمنع تسرب الوسائط على Android الضعيف |
| Service Worker | **Cache-first للأصول المُرقّمة بالإصدار + network-first لبيانات الحساب** | Versioned cache باسم `v{build}` وحذف الكاش القديم عند activate |

## 5) مصفوفة التوافق (Compatibility Matrix) — بديل «كل جهاز في العالم» [توصية]

| الفئة | الضمان | خطة الاختبار |
|---|---|---|
| iPhone (Safari، iOS 15+) | مدعوم كاملًا مع Add-to-Home-Screen يدوي | جهاز iPhone قديم (فئة SE/8) فعلي |
| Android حديث (Chrome 100+) | مدعوم كاملًا مع prompt | جهاز Android ضعيف (2–3GB RAM) فعلي |
| Android قديم (Chrome 80–99) | مدعوم مع تدهور رشيق (بلا prompt) | محاكاة + جهاز فعلي إن أمكن |
| كمبيوتر (Chrome/Edge/Safari/Firefox حديث) | مدعوم | اختبار سريع |
| ما دون ذلك | **غير مضمون** → fallback: نسخة قراءة ويب خفيفة + صفحة دعم توضح المتطلبات | — |

[توصية] الاختبارات الحاكمة قبل الإطلاق: زمن أول تحميل على 4G ضعيف، اختبار RAM على Android بـ2GB، اختبار حذف بيانات الموقع ثم استعادة الرابط، واختبار أول 24 ساعة على iPhone (مسار الإضافة اليدوي).
